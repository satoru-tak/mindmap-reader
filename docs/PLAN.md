# 開発プラン

## コンセプト

本を読みながらマインドマップを作ると理解が深まる、という実体験が出発点。
汎用マインドマップ（XMind、MindMeister など）は無料版の機能が弱く、
「構造化して理解する」ことに特化したツールが無い。そこを埋める。

## 方針

- まずは **読書モード** に絞る。会議モード・AI構造化は後回し
- **Webアプリ** で始める（無料公開、審査なし、PCで読書しながら使う）
- **完全ローカル**：データはブラウザ内に保存。サーバー費用ゼロ、入力内容を外部送信しない
- 最初は **完全無料で公開** し、使われると分かってから課金を入れる

## 設計方針（ADHD/ASD向け）

- 選択肢と設定を絞り、迷わせない
- 入力までの手数を最小にする（開いてすぐ書ける、追加したら即入力）
- 自動整列を標準にし、レイアウトの手間を無くす
- 保存ボタンなし（自動保存）、Undo で誤操作の不安を減らす
- 刺激（色・アニメーション）は控えめ。OSの「視差効果を減らす」設定を尊重

## モード

| モード | 用途 |
|---|---|
| 読書 | 本の理解。ページ番号、引用/自分の言葉、章の型 |
| シンプル | 余計な項目のない普通のマインドマップ（内部値は `free`） |
| 会議（予定） | 聞きながら素早く書く |

## 注意

- 医療的な効果をうたわない（「改善する」ではなく「使いやすい」の表現にする）
- AI機能を入れる場合、APIキーをフロントに置かない（中継サーバー必須）

## 検討中の課題（別途決める）

### 1. 章以外の区切りの単位
本の種類によって区切りの呼び方が違う（小説・ビジネス書＝章、戯曲＝幕・場、漫画＝話・巻）。

- 案：番号は自動で振り、単位（章 / 幕 / 話 / 巻 / 自由入力）をマップごとに選べるようにする
- 例：単位「話」なら「＋ 話を追加」で `第3話` が追加される
- 巻と話の2段（第2巻 → 第10話）のような入れ子も必要か要検討
- 型（要点 / 引用 / 気づき）も単位ごとに変えるか要検討

### 2. 枝を左右に振り分けるか ✅ 対応済み（2026-11-07）
今はすべて右側に伸びる。一般的なマインドマップは左右に振り分ける。

- 意見：読書モードは「上から下へ読む順＝本の順番」になる右側だけが合う。
  シンプル（発想・整理）は左右に振り分けた方が全体を見渡しやすい
- 案：モードごとに既定値を変え（読書＝右のみ、シンプル＝左右）、マップごとに切り替えも可能にする
- 実装で考えること：左側のノードは線の接続位置が逆になる。← / → キーの意味
  （親へ・子へ）を左側では反転させる。ドラッグ時のプレビュー位置も左右対応が必要
- 実装：マップごとに「右だけ / 左右」（読書＝右だけ、シンプル＝左右が既定）。左右のときは上から順に、
  右の高さが全体の半分になるまで右、残りを左（順番は保つ）。枝ごとに 左 / 自動 / 右 を選べる
  （Option+← / →、画面右上の「この枝の位置」、タイトルの左右どちらに落とすか）。左側では ← / → が反転

### 3. 見た目のバリエーション（テーマ） ✅ しくみは対応済み（2026-11-05）
色をただ増やすのではなく、「テーマ」として色・線・ノードの形をまとめて選べるようにする。
見た目を変えられることで飽きずに使い続けられるようにする。

- 基本：シンプルなテーマを標準（無料）にする
- 凝ったテーマは有料の候補
- 刺激を抑える方針（ADHD/ASD向け）とのバランスに注意。落ち着いたテーマは必ず無料で残す
- 実装済み：テーマ＝枝の色（ライト用・ダーク用）・線の形（曲線 / 直角）と太さ・ノードの形（カード / 丸 / 下線）・背景（点 / 罫線）のセット。
  サイドバーの「見た目のテーマ」で選ぶ。選んだテーマはブラウザに保存
- 今あるテーマ：シンプル（標準）・やわらか・ノート。3つとも基本テーマ（無料）（2026-11-05 決定）
- 有料にするのは、今後追加するテーマと細かい配色。課金を入れるときに、鍵を付けるかお試し表示にするかを決める
- 機能・無料と有料の範囲・リリースと宣伝の計画は、計画書（Claude の資料）にまとめた：https://claude.ai/artifact/CQgqKW1L2sKYr9PZ3hQBfB

### 4. ライト / ダーク / システム設定に合わせる の切り替え ✅ 対応済み
- 色はすべて CSS 変数にまとめたので、テーマ（3.）は変数のセットを増やす形で作れる。各テーマにライト版・ダーク版を用意する

### 5. 用途別マップの拡充（XMind との差別化の軸）
汎用ツールの XMind に対して「用途ごとに専用で使いやすい」を売りにする。
読書マップのように、用途に合った型・項目・操作を持つマップを増やす。

- 候補：会議マップ、映画マップ、ビジネスマップ、アニメマップ など
- かなりニッチなマップも用意し、それらを有料にする案
- 区切りの単位（課題1）とも関係する（映画＝シーン、アニメ＝話 など）

### 6. 論理的思考の整理（ロジックマップ）
問い → 答え → 理由 の形で考えを整理する専用マップ。

```
Aを〇〇するには？（問い）
└─ Bこうしたらいい（答え・主張）
    └─ Cなぜなら…（理由・根拠）
```

- ノードに「問い / 答え / 理由」の種類を付け、色や記号で見分けられるようにする
  （読書モードの「引用 / 自分の言葉」と同じ仕組みを流用できる）
- 「理由が無い答え」を目立たせるなど、考えの抜けに気づける工夫も候補
- 用途別マップ（課題5）の有力候補

### 8. PWA（インストール型のWebアプリ）
Dock やホーム画面に置けて、専用ウインドウ・オフラインで動く。無料。
Chrome / Edge（パソコン）なら `.mindmap.json` をダブルクリックで開ける関連付けも可能。公開後に対応。

### 9. XMind ファイルの読み込み
`.xmind`（中身は ZIP。新しい XMind は content.json、XMind 8 は content.xml）を読み込めれば、
XMind からの乗り換えが楽になる。差別化として強い。形式は実装前に要確認。

### 10. ほかのアプリ向けの書き出し・読み込み
独自形式（.mindmap.json）はそのまま残し、共通形式とは変換でやり取りする。
- 書き出し：Markdown / OPML / FreeMind（XMind・MindNode などが読み込める）。
  引用は “ ”、ページは（p.12）として文章に埋め込み、情報が失われないようにする
- 読み込み：Markdown / OPML / FreeMind / XMind
- 独自の拡張子（例：.名前）にするかは名前が決まったときに決める。中身は JSON のまま

### 7. アプリの名前
今の「Mindmap Reader」は仮の名前。ポップで覚えやすい名前を考える。
用途別マップを増やすなら、読書に限定しない名前の方がよい。

### メモ：リポジトリ名の変更
GitHub の Settings → General で変更できる。古い URL は自動転送される。
ただし GitHub Pages の URL は変わり、転送されない。データはドメインごとの保存なので、github.io のままなら残る。
独自ドメインに移すときは、書き出し → 読み込みでデータを移す。
